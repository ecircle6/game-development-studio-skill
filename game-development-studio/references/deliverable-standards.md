# 交付物标准结构（deliverable-standards.md）

> 角色产出前对照本文件。文档头四件套：**文档定位 / 版本 / 上游对齐（引用了哪些文档）/ 硬约束声明**。路径约定：`design/`（策划与美术）、`docs/`（技术与横向规范）、`production/`（计划与发布）、`tests/`（质量）。

## 1. 概念文档（design-strategist · Phase 1）

1. **一句话定位**：题材/平台/时长/目标玩家，一段话说清。
2. **游戏支柱（Pillars）**：3–5 条，作为一切设计取舍的最高准绳。
3. **MDA 分析**：Mechanics / Dynamics / Aesthetics 三段；Aesthetics 必须点明核心 fun（Discovery/Narrative/Expression/Sensation 等的取舍）并解释**为何能成立、为何能避开已知失败**。
4. **核心循环与单局结构**：核心动词链 + 一次会话的节奏曲线（前期即时反馈 → 中期成长 → 末期高潮）。
5. **范围分层**：MVP（最小可玩）/ v1（完整首版）/ Stretch（延展）三档，逐档列关键功能。
6. **题材与合规边界**（虚构化/授权/红线声明）：明确"能用什么、绝不能用什么"。
7. **视觉锚点**：3–5 个可交给美术的参考方向/情绪词。
8. **已知风险与缓解**：影射/合规、技术约束、范围失控、疲劳曲线等。

## 2. 系统 GDD（design-strategist · Phase 2）

- **全局数值字典**：所有跨系统共享的数值键（含义/区间/来源/去向）先行统一，杜绝各系统各算各的。
- 每个系统统一**八节**结构：
  1. 目的与范围（解决什么、边界在哪）
  2. 核心机制（规则、触发、状态）
  3. 玩家交互流程（逐步操作）
  4. 数据与数值模型（字段/阈值，未定的标注"待校准"）
  5. 状态与边界（正常/异常/失败态，防作弊、防卡死）
  6. 系统间耦合（事件/数据流）
  7. 内容与资产需求（给美术/工程/文案的输入）
  8. 验收标准与风险
- **跨 GDD 一致性检查**：列出闭环链路 + 断点清单（每断点给修复并回写进对应系统边界）。
- **设计理论自评**：MDA / 心流（挑战-技能平衡）/ 自我决定论（自主·胜任·关联）/ Bartle 玩家类型，论证系统为何成立。

## 3. 架构文档 + ADR（engineering-lead · Phase 3）

- **主架构**：技术栈选型与理由、模块划分（映射到系统）、状态管理、系统间通信、数据模型、持久化、性能预算、工程化（构建/CI/测试）。
- **ADR ≥3 条**（基础层决策），每条四段：**状态 / 背景 / 决策 / 后果（含正负与逃逸条款）**。
- **架构评审**：按 `quality-gates.md` 输出判定 + 验证矩阵。
- **控制清单**：落地前 Must-Confirm 项，含一致性断点的验证门禁（单测断言 + 静态检查 + 内容 lint 三重保险思路）。
- **诚实声明**：明确列出知识缺口（如纯客户端防篡改的边界、需真机校准的数值）。

## 4. UX 规格（design-strategist · Phase 4）

屏幕流（文字流程图 + 每屏动作/反馈/离场）→ 关键界面线框描述（标注单手拇指区）→ 交互规格（含降级路径）→ 状态转换与反馈点 → 分享/外联流 → **可访问性触点**（动效减弱开关、触控靶、颜色+图标双编码、字体缩放）→ 文案原则。

## 5. 资产规格（art-director · Phase 4）

- **资产清单表**：资产名 / 用途（对应系统界面）/ 格式 / 尺寸与倍率 / 命名规范 / 状态变体。
- **设计令牌**：可直接交付工程的 CSS 变量（色彩/字体/圆角/描边/动效时长）。
- **动效规格**：每条动效给出全开版 + **reduced-motion 降级版**。
- **交付包结构与验收清单**（对比度/双编码/触控靶/降级齐全/红线）。

## 6. 可访问性分级（art-director · Phase 3）

三档递进：**Basic**（对比度 ≥4.5:1、文字缩放、触控靶 ≥44px、颜色+图标/文字双编码）→ **Standard**（+ reduced-motion 降级、字体档位、基础屏幕阅读器语义）→ **Comprehensive**（+ WCAG AA 全量、色盲形状编码、键盘可达、焦点管理）。附 **特性矩阵**（特性 × 三档）与推荐档位及理由。

## 7. Epic/Story 与测试计划（engineering-lead · Phase 4）

- **Epic/Story 拆分**：每条 Story 含简述、验收标准、关联模块。
- **构建顺序**：以"最早验证核心循环"为关键路径排序，并说明理由。
- **测试脚手架计划**：必写测试（数值边界、一致性断点门禁、关键路径覆盖）+ 测试目录 + 示例断言骨架。
- **DoD**：可量化（跑通什么/达标什么/门禁全绿/性能预算）。

## 8. 发布文档（release-ops-lead · Phase 7）

发布清单（逐项勾选）、版本号与变更日志、补丁说明、上线检查清单、本地化覆盖表、**回滚预案**（触发条件 + 步骤 + 责任人）。最终放行以质量负责人签字为前提。

## 9. 设计哲学（所有策划产出的底层依据）

- **MDA**：机制 → 动态 → 美学，评估任何设计先问"产出什么 fun"。
- **自我决定论**：自主（有意义的选择）、胜任（即时反馈与成长）、关联（社交/共同体）三需求是否被机制覆盖。
- **心流**：挑战-技能平衡；警惕认知过载（系统分阶段解锁）。
- **Bartle 玩家类型**：成就者/探索者/社交者/杀手——重玩动机是否覆盖多类型。
- **验证驱动开发**：先写测试/验收标准，再实现；用最小可玩切片验证"好不好玩"再扩展。
